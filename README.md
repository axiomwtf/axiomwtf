We build tools the way they should have been built.<br>
One output. No sidecars. Signed by default.<br>
And no wrappers around someone else's config soup.

<br>

<h3 align="center">How we work.</h3>

<table align="center">
  <tr>
    <td width="50%" valign="top">
      <sub>01</sub><br>
      <b>Take the obvious route</b><br>
      If there's a boring way to do something, that's the way we do it.
    </td>
    <td width="50%" valign="top">
      <sub>02</sub><br>
      <b>Fewer parts</b><br>
      Every extra piece is something that can break later, so we keep cutting until only what's needed is left.
    </td>
  </tr>
  <tr>
    <td valign="top">
      <sub>03</sub><br>
      <b>Mind the small stuff</b><br>
      Little details decide whether a tool feels right, so we spend time on them.
    </td>
    <td valign="top">
      <sub>04</sub><br>
      <b>Our own way</b><br>
      We're independent and opinionated. Nobody signs off on our work but us.
    </td>
  </tr>
  <tr>
    <td valign="top">
      <sub>05</sub><br>
      <b>No sidecars</b><br>
      Companion files and helper processes count as bugs. If something can ship as one file, it ships as one file.
    </td>
    <td valign="top">
      <sub>06</sub><br>
      <b>Easy to maintain</b><br>
      We'd rather write code that's still easy to fix years from now than code that's fashionable today.
    </td>
  </tr>
</table>
